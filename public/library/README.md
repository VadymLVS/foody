# Библиотека изображений

Файлы отдаются статически, в сборку не попадают — размер приложения от них не растёт.
Добавлять можно пачками в любой момент.

## Продукты — `products/`

- **800×800**, квадрат, WebP, качество ~80 (60–120 КБ на файл)
- Предмет по центру и крупно, с запасом по краям: в строке видна узкая
  горизонтальная полоса, вырезанная из центра, её ширина плавает от 154 до 258 px
- Фон тёмный или нейтральный. Снимок на белом превратится в светящийся
  прямоугольник посреди чёрного экрана
- Без надписей и водяных знаков — их срежет непредсказуемо

Имя файла = `key` из `product_suggestions`, например `milk.webp`.

Нужные имена:
milk, kefir, sour_cream, cottage_cheese, cheese, butter, eggs, yogurt,
bread, loaf, potato, carrot, onion, garlic, tomato, cherry_tomato,
cucumber, cabbage, beet, pepper, apple, banana, lemon, orange,
chicken, beef, pork, mince, fish, salmon, rice, buckwheat, pasta,
flour, sugar, salt, oil, tea, coffee, water

## Блюда — `dishes/`

- Длинная сторона **1200**, WebP
- Пропорции намеренно разные: часть 3:4, часть 1:1, часть 4:3.
  На этом разнобое держится кладка — при одинаковых пропорциях она
  выродится в ровные ряды
- Обрезки нет, снимок показывается целиком

Имя файла — латиницей по названию блюда: `plov.webp`, `borsch.webp`.

Для старта хватит десятка. Предлагаемый набор:
omlet, borsch, plov, pasta_carbonara, grechka, salat_cezar, greek_salad,
sharlotka, oladi, zharenaya_kartoshka, kurinyi_sup, losos, syrniki, pure

## Пропорции

При добавлении снимка блюда в базу сохраняются `image_w` и `image_h` —
кладка использует их, чтобы зарезервировать место до загрузки картинки.
Иначе сетка будет прыгать при прокрутке.
