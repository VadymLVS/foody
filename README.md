# PantrySync

Учёт продуктов и выбор блюд для семьи. Открываешь перед магазином — видишь,
чего не хватает. Утром свайпаешь блюда — получаешь план дня и список покупок.

Документация — в папке `docs/`. Начинать с `00-decisions-and-changelog.md`:
там зафиксированы все принятые решения. Если код и документ расходятся —
прав документ, код надо чинить.

## Запуск

```bash
npm install
cp .env.example .env      # можно пропустить: без ключей включится демо-режим
npm run dev
```

Без ключей Supabase приложение поднимается на демо-данных: 15 продуктов,
6 категорий, всё переключается и переживает перезагрузку. Тот же режим
понадобится ревьюеру App Store, который не станет регистрироваться
(Guideline 2.1).

Витрина дизайн-системы — `/dev/ui`, только в дев-сборке.

## База

```bash
supabase db push          # или вручную через SQL Editor, по порядку
npm run db:types          # перегенерировать типы после изменений схемы
```

| Файл | Содержимое |
|------|-----------|
| `0001_schema.sql` | Таблицы, индексы, констрейнты, триггеры |
| `0002_rls.sql` | Row Level Security — единственный слой авторизации |
| `0003_functions.sql` | RPC: кухни, приглашения, удаление аккаунта, колода свайпов |
| `0004_storage.sql` | Бакет для фото блюд и политики доступа |
| `0005_seed.sql` | Системные категории и справочник автокомплита |

**Перед первым деплоем пройти чеклист в `docs/04-security.md` §11.**
Половина пунктов закрывает ошибки, найденные в первой версии спеки.

## Структура

```
src/
  app/        роутер и провайдеры
  features/   экраны по доменам
  shared/
    api/      репозиторий: Supabase + демо-реализация
    db/       типы (после db:types — сгенерированные)
    hooks/    запросы и мутации
    lib/      voice, image, text, platform
    store/    UI-состояние (Zustand)
    ui/       дизайн-система
supabase/migrations/
```

## Правила, которые нельзя нарушать

1. **Никакого серверного рантайма.** Ни API routes, ни middleware. Сборка
   статическая, иначе приложение не упакуется в Capacitor (D-002).
2. **Сессия в нативной сборке — только Keychain**, не localStorage.
3. **`SUPABASE_SERVICE_ROLE_KEY` не появляется в этом репозитории никогда.**
   Он обходит RLS.
4. **Каждая новая таблица получает RLS в той же миграции**, где создаётся.
   Таблица без RLS в Supabase открыта на чтение и запись всем.
5. **Для голоса проверять платформу, а не наличие API**: в WKWebView объект
   `webkitSpeechRecognition` есть, но не работает (D-013).
