## 2. Экран «Список» (`/products`)

Главный экран, открывается по умолчанию.

### 2.1 Шапка (sticky)

- **Название кухни** — tappable, открывает Bottom Sheet переключения.
- **Индикатор соединения** — точка 8px рядом с названием. Зелёная = реалтайм-канал подключён, жёлтая = переподключение, серая = офлайн. Реализуем: это единственный честный способ объяснить, почему изменения не видны.
- **Аватар профиля** — справа, ведёт в `/settings`.

### 2.2 Поиск

- Поле с иконкой `Search` слева и `Mic` справа.
- Placeholder: «Найти продукт…»
- **Активация с 2 символов** **▲ D-008** (было 3 — ломало «яйцо», «мука», «соль»).
- **Логика: подстрока, не префикс** **▲ D-008**. Нормализация: lowercase, `ё → е`, схлопывание пробелов. Результаты сортируются: сначала совпадения с начала названия, затем остальные.
- Если результатов нет — кнопка «Создать "[введённое]"», открывает модал добавления с предзаполненным названием.
- Кнопка микрофона **скрывается**, если голосовой ввод недоступен на платформе **▲ D-013**. Не показываем неработающую кнопку.

### 2.3 Фильтр категорий

Горизонтальный скролл pills: `[Все] [Овощи] [Фрукты] [Молочка] [Мясо] …`
Активная — заливка Accent, белый текст. Неактивная — обводка, тёмный текст.

Порядок категорий **фиксированный, не алфавитный** **▲ D-007** — примерно как расположены отделы в магазине:
`Овощи → Фрукты → Молочка → Мясо и рыба → Хлеб → Бакалея → Заморозка → Напитки → Сладкое → Бытовое → Прочее`

### 2.4 Фильтр статуса

Сегменты: `[Купить] [В наличии] [Все]`. По умолчанию — **Купить**.

### 2.5 Список продуктов

**Группировка по категориям со sticky-заголовками** **▲ D-007**. Внутри категории — алфавит.
Если активен фильтр по одной категории — заголовки не показываются.

#### Карточка продукта

**Визуально:**
- Белый фон, скругление 12px, padding 16px, высота 64px.
- Название слева (16px, semibold).
- Количество справа от названия — **только если `in_stock = true` и `quantity > 0`** (14px, TextMuted). Формат: «2 л», «500 г».
- Тоггл iOS-style справа, 51×31px.
- Иконка `MoreVertical` справа от тоггла. Визуально 20px, **кликабельная зона 44×44px** **▲ D-014**.

**Взаимодействия:**

| Действие | Результат |
|----------|-----------|
| Тап по тогглу | Мгновенное переключение. При включении — разворачивается панель количества |
| Тап по карточке (не тоггл) | Если ON — открыть панель количества. Если OFF — включить и открыть панель |
| Долгое нажатие (500ms) / правый клик | Контекстное меню |
| Свайп влево | Удалить (с toast «Отменить») — опционально, MVP-2 |

Тап по карточке в состоянии OFF **включает продукт** — это самый частый сценарий в магазине, попадать в тоггл на ходу неудобно.

### 2.6 Панель количества

Разворачивается под карточкой, анимация `height 0 → auto`, 200ms, `ease-out`.

**Содержимое:**
- Фон AccentLight (#E8F5E9), высота 56px.
- Слева: «Количество, [единица]»
- Справа: `[−] [число] [+]`
- Шаг: для `шт`/`упак` — 1; для `кг`/`л` — 0.5; для `г`/`мл` — 50.
- Долгое нажатие на `+`/`−` — автоповтор.

**Закрытие:** тап по другой карточке, тап по тогглу этой карточки, тап по фону, кнопка «Назад» на Android. Авто-таймера нет.

**При выключении тоггла:**
- Панель закрывается сразу.
- **Количество НЕ сбрасывается** **▲ D-006**. Оно просто перестаёт отображаться. Вернул тоггл — количество на месте.

### 2.7 Контекстное меню

- `Pencil` Переименовать
- `Ruler` Изменить количество
- `FolderInput` Сменить категорию **▲ новое** (раньше требовало удалить и создать заново)
- `Trash2` Удалить (красным)

### 2.8 Удаление продукта **▲ D-009**

Модалки подтверждения **нет**. Продукт исчезает из списка мгновенно, внизу на 5 секунд появляется toast:

> Молоко удалено · **Отменить**

Технически — soft delete (`deleted_at`), физическое удаление фоном через 30 дней.
Если продукт используется в блюдах — toast дополняется: «Используется в 2 блюдах».

### 2.9 Модал «Добавить продукт»

- Поле «Название» с автокомплитом по общему справочнику `product_suggestions` (от 2 символов). При выборе подсказки категория и единица подставляются автоматически.
- Селект «Категория» + пункт «Создать новую».
- Селект «Единица»: шт, кг, г, л, мл, упак.
- Чекбокс «Уже в наличии» (по умолчанию выключен).
- Кнопки: `[Отмена] [Добавить]`
- **Дубликаты:** если продукт с таким названием уже есть на кухне — вместо создания показываем «Молоко уже есть в списке» и предлагаем перейти к нему.

### 2.10 Прочие модалы

| Модал | Поля | Кнопки |
|-------|------|--------|
| Переименовать | Текущее название | Отмена / Сохранить |
| Изменить количество | `[−] [число] [+]` + единица | Отмена / Сохранить |
| Сменить категорию | Список категорий с радио | Отмена / Сохранить |
| Новая категория | Название | Отмена / Создать |

### 2.11 Пустые состояния

| Условие | Текст |
|---------|-------|
| Фильтр «Купить», всё в наличии | «Всё есть. Можно готовить 🎉» + кнопка «Посмотреть блюда» |
| На кухне нет продуктов вообще | «Здесь пока пусто» + кнопка «Добавить первый продукт» + «Загрузить типовой набор» |
| Нет ни одной кухни | «Создайте свою первую кухню» + кнопка |
| Поиск без результатов | «Не найдено» + кнопка «Создать "[текст]"» |

«Загрузить типовой набор» — 25 базовых продуктов (соль, сахар, масло, яйца, хлеб…), все выключены. Резко снижает порог входа.

### 2.12 FAB

Кнопка «+», 56px, правый нижний угол, отступ 16px + safe area. Открывает модал добавления.

## 3. Экран «Блюда» (`/dishes`)

### 3.1 Шапка
Заголовок «Блюда», справа — `Plus`. В режиме планирования — «Отмена».

### 3.2 Фильтры
Pills: `[Все] [Можно приготовить] [Не хватает]`

### 3.3 Сетка
2 колонки на мобильном, 3 на планшете, 4 на десктопе. Gap 12px.

**Карточка блюда:**
- Фото 16:9, скругление 12px. Если фото нет — плейсхолдер с первой буквой названия на цветном фоне (цвет детерминированно из id).
- Название под фото, 16px semibold, максимум 2 строки.
- Индикатор:
  - Зелёная точка + «Готово» — все ингредиенты в наличии.
  - Серое «Не хватает 3» — с числом.

### 3.4 Режим планирования
Активация: кнопка «Спланировать» в шапке.
Чекбоксы в углу карточек. Sticky-панель снизу: «3 блюда · Список покупок» + «Очистить».

### 3.5 Модал «Список покупок»
- Заголовок: «Покупки для 3 блюд»
- Группировка по категориям.
- Недостающие продукты с чекбоксами «Куплено» → при отметке продукт переключается в `in_stock = true` на кухне.
- Кнопка «Скопировать список» — plain text в буфер, для отправки в мессенджер.

### 3.6 Детали блюда (`/dishes/[id]`)
- Фото на всю ширину, 200px.
- Название 24px bold.
- Ингредиенты: `Check` зелёный + жирный (есть) / `X` серый (нет). Тап по отсутствующему — включает его в наличии.
- Кнопка «Я приготовил это» — MVP-2. Выключает израсходованные ингредиенты (с диалогом выбора, что именно закончилось).

### 3.7 Модал «Добавить блюдо»
- Поле «Название».
- Фото: кнопка «Добавить фото» → камера или галерея. **EXIF стрипается на клиенте** **▲ D-017**.
- Ингредиенты: поиск по продуктам кухни с автокомплитом, кнопка «+ Создать продукт» открывает вложенный модал и возвращается обратно. Список добавленных с крестиком.
- Кнопки: `[Отмена] [Сохранить]`

### 3.8 Пустое состояние
«Нет сохранённых блюд» + «Добавить первое блюдо» + «Загрузить примеры» (5 базовых блюд с ингредиентами).

## 4. Свайп-режим «Что сегодня едим» **▲ D-004, MVP-1**

Центральная функция продукта. Всё остальное существует, чтобы этот экран знал, что лежит дома.

### 4.1 Запуск

| Способ | Условие |
|--------|---------|
| Автоматически | Первый вход после 05:00, если на сегодня плана ещё нет. Полноэкранно, с кнопкой «Позже» |
| Вручную | Кнопка «Что едим?» в шапке экрана «Блюда» |
| Из списка | Карточка-подсказка вверху экрана «Список», если план не заполнен |

Не запускается автоматически: если план на сегодня уже есть, если на кухне меньше 3 блюд, если выключено в настройках.

### 4.2 Колода **▲ D-020**

Порядок не случайный:

1. Блюда, для которых **всё есть** — перемешаны, но со сдвигом: те, что давно не выбирались, идут раньше (иначе колода вырождается в одни и те же три позиции). Дата последнего выбора берётся из `meal_plans`.
2. Блюда, где **не хватает 1–2 ингредиентов** — с пометкой «нужно докупить: молоко».
3. Блюда, где не хватает трёх и больше, **не показываются вообще**.

Максимум 20 карт за сессию — дальше это уже не выбор, а листание.

### 4.3 Карточка

- Фото на всю карту, скругление 20px, градиентное затемнение снизу.
- Название — `Title`, белым, поверх затемнения.
- Строка статуса: «Всё есть» (зелёная точка) или «Нужно докупить: молоко, хлеб».
- Сверху — текущий слот: «Завтрак» / «Обед» / «Ужин».
- Индикатор прогресса: 3 точки, заполненные по числу выбранных блюд.
- Тап по карточке — детали блюда (не свайп).
- Если фото нет — плейсхолдер с крупной первой буквой на детерминированном цвете.

### 4.4 Жесты

| Действие | Результат |
|----------|-----------|
| Свайп вправо / кнопка `Check` | Блюдо занимает текущий слот, переход к следующему |
| Свайп влево / кнопка `X` | Пропустить |
| Кнопка `Undo` | Отменить последний свайп (один уровень) |
| Тап | Открыть детали блюда |

- Карта поворачивается при перетаскивании (до 12°), порог срабатывания — 40% ширины экрана или скорость выше 0.5 px/ms.
- **Кнопки-дублёры обязательны**, не «на будущее»: свайп одной рукой на большом экране неудобен, и жест недоступен с клавиатуры.
- В нативной сборке — тактильный отклик на каждое срабатывание.
- `prefers-reduced-motion` — карты меняются без анимации перелёта.

### 4.5 Завершение

Три свайпа вправо → экран **«План на сегодня»**:
- Три блюда с фото и названиями.
- Общий список недостающих продуктов, сгруппированный по категориям.
- Кнопка «Добавить в покупки» — переводит недостающее в список со статусом «купить».
- Кнопка «Переделать» — сбрасывает план и запускает колоду заново.

Если карты кончились раньше:
- «Блюда закончились» + «Добавить блюдо» + «Показать те, где не хватает многого».

### 4.6 Реакции на серию отказов **▲ D-021**

Показываются поверх колоды при 5, 10, 15 и 20 свайпах влево **подряд**. Счётчик сбрасывается любым свайпом вправо.

| Порог | Пример фразы |
|-------|--------------|
| 5 | «Ну хоть что-то же ты ешь?» |
| 10 | «Может, просто чай?» |
| 15 | «Холодильник смотрит на тебя с надеждой.» |
| 20 | «Ладно. Доставка так доставка.» |

Правила:
- Фраза не повторяется, пока не исчерпан весь банк.
- Не показывается в первый день использования — человек ещё не понял правила игры.
- **Отключается в настройках.** На третий день это может раздражать, и это нормально.
- Тон: мягкий, без упрёка. Приложение подшучивает над ситуацией, не над человеком.

### 4.7 План дня (`/today`)

- Три слота: завтрак, обед, ужин. Пустой слот — кнопка «Выбрать».
- **План персональный** **▲ D-019**. Ниже — строка «Арина выбрала: Борщ» по остальным участникам. Перезаписать чужой выбор нельзя.
- Кнопка «Я приготовил это» — открывает диалог «Что закончилось?» со списком ингредиентов и чекбоксами, отмеченное переключается в «купить».
- История планов — MVP-2.

### 4.8 Настройки режима

- Утренний запуск: вкл / выкл
- Количество слотов: 1 (только ужин) / 2 / 3 — по умолчанию 3
- Реакции на отказы: вкл / выкл

## 5. Экран «Настройки» (`/settings`)

### 5.1 Текущая кухня
Название (tappable → управление), ряд аватарок участников (макс 3, дальше «+N»).

### 5.2 Мои кухни
Список с радиокнопкой активной. Кнопка «+ Создать новую кухню».

### 5.3 Профиль
Аватар 64px, имя, email. Кнопка «Выйти».

### 5.4 Аккаунт **▲ D-018 · новое**
Отдельный блок внизу:
- «Удалить аккаунт» (Danger, приглушённый)
- Ведёт на экран `/settings/delete-account` с описанием последствий:
  - какие кухни будут удалены (те, где вы единственный участник),
  - в каких владение перейдёт другому участнику,
  - что действие необратимо.
- Требует ввода `УДАЛИТЬ` в поле подтверждения.

Это требование App Store Guideline 5.1.1(v), но делаем сразу и для веба.

### 5.5 Bottom Sheet «Переключение кухни»
Список кухонь: название, число участников, галочка активной. Кнопка «+ Создать кухню».

### 5.6 Управление кухней (`/kitchens/[id]`)

**Название** — текст + `Pencil`.

**Приглашение** **▲ D-011:**
- Ссылка (сокращённо) + кнопка «Копировать» + системный Share.
- Подпись: «Действует до 4 августа»
- Кнопка «Обновить ссылку» — старая мгновенно перестаёт работать (с подтверждением).
- Переключатель «Приглашения включены».

**Участники:**
Аватар + имя + email + роль (Владелец / Участник). Кнопка удаления — только для владельца. «Покинуть кухню» — для себя, если не владелец.

**Опасная зона:**
«Удалить кухню» — только владелец, с подтверждением вводом названия кухни.

## 6. Регистрация и вход

### 6.1 Welcome
Логотип, слоган «Продукты и блюда для всей семьи», кнопки «Создать кухню» / «У меня есть приглашение».

### 6.2 Регистрация / вход
Email + пароль. Минимум 8 символов, проверка на утёкшие пароли на стороне Supabase **▲ см. 04-security.md**.
Ссылка «Уже есть аккаунт? Войти».

### 6.3 Присоединение (`/join/[code]`)
- «Вас пригласили в кухню "Дом"» + аватар пригласившего.
- Не авторизован → форма регистрации, после — автоматическое вступление.
- Авторизован → кнопка «Присоединиться».
- Код истёк / отозван → «Приглашение больше не действует. Попросите новую ссылку».
- После вступления — редирект в `/products` с этой кухней как активной.

## 7. Права доступа

| Роль | Может |
|------|-------|
| **Владелец** | Всё + удалить кухню + управлять приглашениями + удалять участников |
| **Участник** | CRUD продуктов и блюд, переименовать кухню, покинуть кухню |

- Участник **не может** удалять других участников **▲ изменено** (в v0.1 мог — это давало возможность выкинуть всю семью).
- Если владелец покидает кухню — владение переходит участнику с самой ранней датой вступления.
- Если владелец удаляет аккаунт — то же самое; если участников нет — кухня удаляется.

---

## 8. Голосовой ввод **▲ D-013**

- Абстракция `VoiceInput` с двумя реализациями (браузер / нативная обёртка).
- Язык `ru-RU`. Результат вставляется в поле поиска, поиск запускается автоматически.
- Fuzzy matching и AI-обработку не делаем.
- Кнопка не отображается, если реализация недоступна.

## 9. Обработка ошибок и сети

| Ситуация | Поведение |
|----------|-----------|
| Тоггл не сохранился | Откат состояния + toast «Не удалось сохранить. Проверьте соединение» |
