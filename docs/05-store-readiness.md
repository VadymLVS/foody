# PantrySync — Готовность к публикации

> Стратегия зафиксирована в **D-001**: сначала PWA, магазины — позже. Этот документ описывает, что должно быть в коде **с первого дня**, чтобы переход в магазины не потребовал переписывания.

---

## 1. Почему не App Store сразу

Guideline 4.2 (Minimum Functionality) требует, чтобы приложение содержало функции, контент и интерфейс, выходящие за рамки переупакованного сайта. PantrySync в объёме MVP-1 — список, тогглы, модалки — целиком воспроизводится в браузере. Типичный исход: отказ с формулировкой «сделайте HTML5 веб-приложение и распространяйте его со своего сайта».

Цена отказа не только во времени: после реджекта следующая подача рассматривается дольше и лишается права на ускоренное ревью.

**Условие для подачи в App Store:** в приложении должна появиться хотя бы одна функция, невозможная в мобильном Safari.

Кандидаты по убыванию убедительности:
1. **Сканирование чека камерой** с распознаванием покупок (V2) — самая сильная заявка.
2. Локальные уведомления («вечером спросить, что готовим завтра»).
3. Виджет на домашний экран со списком покупок.
4. Siri Shortcuts / App Intents («добавь молоко в список»).
5. Live Activity со списком покупок на локскрине во время похода в магазин.

Первого пункта достаточно. Первого + любого второго — с запасом.

**Google Play** значительно мягче к веб-обёрткам. Разумный порядок: PWA → Play → App Store.

## 2. Этап 1: PWA

### Что нужно
- [ ] `manifest.webmanifest`: `name`, `short_name`, `description`, `start_url`, `display: standalone`, `theme_color: #34C759`, `background_color: #F5F5F7`, `orientation: portrait`
- [ ] Иконки: 192, 512, 512 maskable, `apple-touch-icon` 180×180
- [ ] Service worker (`vite-plugin-pwa`, стратегия: precache оболочки, network-first для данных)
- [ ] `<meta name="apple-mobile-web-app-capable" content="yes">`
- [ ] `<meta name="apple-mobile-web-app-status-bar-style" content="default">`
- [ ] `viewport-fit=cover` + `env(safe-area-inset-*)`
- [ ] Splash-экраны для iOS (генерируются, но Safari требует их отдельными тегами для каждого размера — берём генератор)
- [ ] Подсказка «Установить на домашний экран» — баннер при третьем визите, с инструкцией для iOS (там нет `beforeinstallprompt`)

### Ограничения, которые надо принять
- Веб-пуши на iOS работают только для PWA, добавленных на домашний экран, начиная с iOS 16.4.
- Данные в браузерном хранилище iOS могут быть вычищены после ~7 дней неиспользования. Для нас не критично: всё в Supabase, локально только UI-настройки.
- Голосовой ввод **работает** в Safari, но не будет работать в будущей нативной обёртке — см. **D-013**.
- Нет присутствия в поиске App Store. Распространение — через ссылку.

## 3. Этап 2: подготовка кода к Capacitor

Это делается **сейчас**, даже если обёртки не будет ещё год. Каждый пункт — цена одного дня сегодня против недели рефакторинга потом.

| Требование | Статус |
|-----------|--------|
| Сборка полностью статическая, без серверного рантайма (**D-002**) | Заложено |
| Абстракция голосового ввода (**D-013**) | Заложено |
| Абстракция хранилища сессии (localStorage / Keychain) | Заложено, §4 в `04-security.md` |
| Все размеры в `rem`/`px`, никаких `vh` (ломается о клавиатуру в WKWebView) | Правило |
| Safe area insets (**D-014**) | Заложено |
| Роутинг без зависимости от серверных редиректов | Заложено |
| Никаких `window.open` для внешних ссылок — только `@capacitor/browser` через абстракцию | Правило |
| Файловый ввод через абстракцию (в нативе — `@capacitor/camera`) | Заложено |
| Все внешние запросы — только к `*.supabase.co` (упрощает ATS-конфиг iOS) | Правило |

## 4. Обязательные требования App Store

Их проще заложить сразу, чем встраивать после отказа.

| # | Требование | Guideline | Где реализуем |
|---|-----------|-----------|---------------|
| 1 | **Удаление аккаунта внутри приложения** | 5.1.1(v) | `/settings/delete-account`, **D-018** |
| 2 | Политика конфиденциальности по публичному URL | 5.1.1 | Отдельная страница на домене + ссылка в настройках |
| 3 | Support URL | — | Страница на домене |
| 4 | Privacy Nutrition Labels в App Store Connect | 5.1.2 | Заполняются честно: Email, Name — linked to user, не для трекинга |
| 5 | **Sign in with Apple**, если есть сторонний соцлогин | 4.8 | Пока только email+пароль → не требуется. Добавим Google — потребуется |
| 6 | Строки-описания для разрешений | — | `NSCameraUsageDescription`, `NSPhotoLibraryUsageDescription`, `NSMicrophoneUsageDescription`, `NSSpeechRecognitionUsageDescription` — на русском и английском |
| 7 | Приложение работает без логина хотя бы в демо-режиме, либо ревьюеру дан тестовый аккаунт | 2.1 | Обязательно завести demo-аккаунт с наполненной кухней и указать в App Review Notes |
| 8 | Возрастной рейтинг | — | 4+ |
| 9 | IAP — нет платного контента | 3.1.1 | Не применимо, приложение бесплатное |
| 10 | Скриншоты для всех требуемых размеров экрана | — | Генерировать из Figma |

**Отдельно про пункт 7:** самая частая причина «технического» отказа — ревьюер не смог зайти. Тестовый аккаунт + логин/пароль + пометка «данные предзаполнены» в App Review Notes обязательны.

### Universal Links (инвайт-ссылки)

Без этого `/join/[code]` откроет Safari вместо приложения.

- [ ] `apple-app-site-association` на `https://<домен>/.well-known/`, отдаётся с `Content-Type: application/json`, без редиректов
- [ ] Associated Domains capability в Xcode: `applinks:<домен>`
- [ ] Android: `assetlinks.json` + intent-filter с `android:autoVerify="true"`
- [ ] Фолбэк: если приложение не установлено — веб-версия отрабатывает тот же сценарий

## 5. Google Play

- [ ] Data Safety форма (аналог privacy labels)
- [ ] Target SDK не ниже текущего требования Play (проверить на момент подачи)
- [ ] Политика конфиденциальности — тот же URL
- [ ] Удаление аккаунта: и в приложении, и **веб-форма по публичной ссылке** — Play требует внешний способ
- [ ] Подпись релиза, Play App Signing
- [ ] Разрешения только используемые: `CAMERA`, `RECORD_AUDIO`. Никаких `ACCESS_FINE_LOCATION`

## 7. Порядок действий

```
Сейчас      → MVP-1 как PWA, деплой на Vercel, домен, HTTPS
              Использование в семье, сбор реальных проблем
              ↓
+1–2 мес    → MVP-2: свайп-режим, план дня, характер приложения
              ↓
+3 мес      → Capacitor-сборка под Android, публикация в Play
              (мягкое ревью, отработка процесса)
              ↓
+4–6 мес    → V2: сканирование чека камерой
              → только после этого подача в App Store
```

Ключевая мысль: не подавать в App Store, пока в списке функций нет ничего, чего не может Safari. Один отказ портит условия для всех последующих подач.
